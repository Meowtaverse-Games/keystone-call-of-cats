## 残した構造とランダム範囲

13〜19は `0d57857` 時点の `design/stages` から主要課題を切り出し、start chunkに固定。13〜16は入口を少し前へ移し、降りて主要課題へ近づく区間を追加。旧石の位置・主要操作は維持した。17〜19は初期位置と中間足場を維持した。

主要パズルより後に短い通路、天井の岩、出口の小さな下りを接続する。必要な配置・採掘数や石の役割はチャンク抽選で変わらない。13〜16には低い下り段差のmiddle候補も含める。17〜20は乗り継ぎ等の負担を優先し、出口の変化を小さくした。

主に余白だった右側をチャンクへ分割した候補であり、mainの既存1〜12をこの構造へ置換するものではない。多い地形数そのものを面白さの証明としない。

## 対照試験で確認したこと

- 13〜16: 石操作なし、配置上限0では各100件とも失敗。16は石0または1の操作を省いた場合も全件失敗。
- 17〜19: 全石の操作を省いた場合、または片方の石の操作を省いた場合に、各100件とも到達経路なし。
- 20: 全石または片方の石の操作を省いた場合、各100件とも到達経路なし。
- 14/15/16/20: 上限をそれぞれ6/5/3/4へ1個減らすと、同じ配置手順は全100件で資源不足を検出。

26条件×100 seedの負の対照を保存した。これらは指定手順・静止状態の比較であり、別コードで1石や少ない配置数で解けないという網羅的証明ではない。17〜20の片石省略試験は残ったプレイヤー操作の空振りで早期中断せず、最後の到達経路を判定した。

20の初案では、下側の石が動かさなくても足場になり、上側だけの操作でクリアできた。最終候補では下側用の石の初期位置を上げ、降ろして橋を作る役割を明確にした。旧3石候補から単に1個削ったものではない。

## 再現

リポジトリルートから。出力先は新規ディレクトリを使う。

```bash
sim() { cargo run --quiet --locked --manifest-path tools/stage_sim/Cargo.toml -- "$@"; }
sim play 13 --stage-file design/prototypes/stages-13-20-v1/stage-13.ron --seed 0
sim check 13 --stage-file design/prototypes/stages-13-20-v1/stage-13.ron \
  --plan design/prototypes/stages-13-20-v1/stage-13.plan \
  --seeds 100 --walk-to-goal --require-initially-unreachable --reject-blocked \
  --output /tmp/stage13-candidate-review
sim simulate 18 --stage-file design/prototypes/stages-13-20-v1/stage-18.ron \
  --plan design/prototypes/stages-13-20-v1/evidence/stage-18-seed-0.plan \
  --seed 0 --require-goal
```

13を14〜20に置き換えて他の候補を確認できる。全件再実行は `bash design/prototypes/stages-13-20-v1/verify.sh`。Bevy本体はビルドしない。

[evidence/summary.json](evidence/summary.json)に候補・planのSHA-256、設定、結果、チャンク出現回数と負の対照の操作・エラーを保存。各面の`*-ascii.txt`は最大3つの代表配置、`*-layout-seeds.json`は全seedと代表seedの対応。成功したseed 0の完全操作列8本を保存先から再実行して確認済み。外部`/tmp`の全reportは永続保証がないため、ソース・操作・再現方法をここに残した。
