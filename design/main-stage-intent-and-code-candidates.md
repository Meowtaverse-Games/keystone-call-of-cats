# main時点のステージ意図と解法コード案

調査日: 2026-09-28。対象: `origin/main` / `43a8df9`。統合ブランチの固定20面候補の解法をmainの解法として流用していない。

## 分かった範囲

- mainにはStage 1〜12の地形がある。日本語説明では1〜6が移動・待機・反復、7〜8が接触制御、9〜12が採掘・空き判定である。
- 13〜23は一覧と説明に構想が残っているが、地形ファイルとロード分岐がない。実装済みの面としては扱えない。
- mainの追跡ファイルに面別の完成解法集は見つからない。`StageScripts`はユーザーが入力したコードの保存機能であり、正解集ではない。
- PR #51（Stage 5〜8）と#52（Stage 9〜12）は本文・コメントに解法がなく、PR #70は「複数ストーンが登場するステージに対応」という実装説明のみ。
- 以下のコードはRhai表記の解法候補・骨格。mainの実機クリア確認済みコードではない。方向は地形からの推定、移動回数・待機秒数・プレイヤー動線は面ごとの確認が必要。

## Stage 1〜12

「説明」はmainの日本語文言から読める意図、「地形」はRONの観測。「候補」は今回の推定であり、作者が用意した正解という意味ではない。

| 面 | 説明から分かる意図 | 地形・石 | コードの核となる候補 | プレイヤーの遊び／未確定点 |
| ---: | --- | --- | --- | --- |
| 1 | 地下へ下り、崩れた足場・段差を越える | Type1。必須middle chunkにSがある | コード不要 | 石の存在と操作必須を分ける。生成後の地形で下降と着地を確認 |
| 2 | 道を塞ぐ石を下へ動かす | Type1。開始chunkの狭い通路。石に横0.5の位置補正 | `move("down");` | 1命令の結果として通路が開く。補正込みの通り抜けは実機確認 |
| 3 | 石に乗り、連続移動で崖を渡る | Type1。必須chunkの左に石、右に対岸 | `move("right");`を対岸に届く回数並べる | 搭乗と下車を含む。最初から搭乗済みという説明ではない |
| 4 | 上下左右を組み合わせ、大きな崖を越える | Type1。石は入口より低い位置、右に高い壁 | 上へ移動→右へ移動→必要なら下へ移動 | どの高さなら壁を越えられるか読む。正確な方向順・回数は未確定 |
| 5 | 離れた石にsleepで待ってもらう | Type1。入口側に長い下降地形、先の必須chunkに石 | `sleep(待機秒数);`→右移動を必要回数 | 石までの移動時間と出発を合わせる。秒数を根拠なく固定しない |
| 6 | 長い石移動をloopで簡潔に書く | Type1。入口の床より下に石、右へ空間が続く | `loop { move("right"); }`を水平移動の試験候補にする | loopの公式ヘルプ例は上方向だが、面の完全解法ではない。搭乗・高さ調整は別途必要 |
| 7 | sleepを使えない石に、触れたとき動いてもらう | Type2。下降する足場群、底近くの右側に石 | `loop { if is_touched() { move("up"); } }` | 石へ下って到達し、接触による上昇を試す。上方向は地形からの推定 |
| 8 | 時間で通れるようになる障害物と接触待ち | Type2。入口から下る。石は元RONの列11・行17 | `loop { if is_touched() { move("up"); } }`を最初に試す | 元地形では石の上が開いている。統合試作の右移動9回をmainの正解にしない |
| 9 | 埋まった石をdigで出す。採掘上限5回 | Type3。石の下も岩 | `dig("down"); move("down");`を起点に移動を組む | 掘って移動可能になる体験。右への運搬・出口までの移動は別途確認 |
| 10 | 複数箇所でdigとmoveを組み合わせる | Type3。長い下降地形の底付近に石、その下・周辺に岩 | `dig(方向); move(方向);`を必要箇所で並べる | RON上で石の右は空いており、右移動だけの短縮解も要調査。説明だけから採掘必須と断定しない |
| 11 | 離れた石にタイミングを工夫して掘ってもらう | Type3が2個。上側の石の直下に3個の連続岩、もう1個は左下 | 上側: 接触待ち→下へ採掘・移動×3。下側: 役割未確定 | 2石必須の解法や役割分担は記録されていない。詳細は後述 |
| 12 | 空洞と岩を区別し、5回だけ掘る | Type3が1個。石の真下の列に岩がちょうど5個 | 下が空いていなければdigし、下へmoveする反復 | 空き判定の意図と地形の対応が明瞭。開通後のプレイヤー動線・ゴールは未検証 |

### 読みやすいコード例

Stage 2は説明に直接対応する最小例:

```rhai
move("down");
```

Stage 3は同じ命令の連続。以下は3回分の書式例であり、必要回数を確定した解ではない:

```rhai
move("right");
move("right");
move("right");
```

Stage 5は石へ到達するまで待ってから動かす。以下の5秒・3回は書式例で、受入値ではない:

```rhai
sleep(5);
move("right");
move("right");
move("right");
```

Stage 7・8の接触待ち候補。接触している間だけ上昇し、離れると次の移動命令を発行しなくなる。すでに発行された1移動を接触喪失で即中断する意味ではない:

```rhai
loop {
    if is_touched() {
        move("up");
    }
}
```

Stage 12の採掘判断の骨格:

```rhai
loop {
    if !is_empty("down") {
        dig("down");
    }
    move("down");
}
```

これは下向きの掘削経路を作る候補で、ゴールまでの完成コードではない。末端では地形や外周にも掘ろうとするため、終了位置・搭乗待ち・その後の動作を確定してから製品の正解例にする。

Stage 12の元RONは、上から0始まりで石が列13・行1にあり、同列の行3・4・6・8・9が岩。岩がない行でdigを使わない、という説明と一致する。統合候補の水平採掘へ置き換える前に、この縦の遊びを評価する価値がある。

## Stage 11の2石をどう読むか

元RONを上から読むと、上側の石は列13・行6、下側の石は列2・行17にある。現行の石番号順では上側が石0、下側が石1となる。

```text
入口 ── 時間で消える障害物・岩塊
                         石0
                          岩
                          岩   ← 直下に連続3マスの岩
                          岩
                          空間

石1 ── 下側の障害物 ── 空間 ── 右側出口
```

図は位置関係の要約であり、そのまま歩ける経路を表していない。

**観測できること**:

- 2個のSは地形変更コミット`0982cfa`で追加され、mainに残っている。
- 両方ともType3、採掘上限はそれぞれ5回。コードは石別に編集し、同時実行できる。
- 上側の石の直下3マスを掘ると縦の空間につながる。
- 説明は「離れた石」「タイミングを工夫して掘る」。2石を必ず使う、乗り継ぐ、合図を送る、などの指定はない。
- 地形追加の履歴・関連PRから、2石それぞれの完成解法は確認できなかった。

**上側の石の試験コード案**:

```rhai
loop {
    if is_touched() {
        dig("down");
        move("down");
        dig("down");
        move("down");
        dig("down");
        move("down");
        break;
    }
}
```

先にis_emptyを必須にせず、見えている連続岩を3回掘る案。接触位置、下降中の搭乗、掘削後の出口への経路は実機で確認する。これは当時の正解コードの復元ではなく、上側の地形を調べるための候補である。

**下側の石には、この時点で正解らしいコードを割り当てない**。水平運搬、上昇、別経路などの仮説は立つが、地形から必要性を確認せずに役割を決めると新設計になる。

次の順で評価する:

1. 上側だけ操作し、下側を静止させてクリアできるか。
2. 下側だけ操作し、上側を静止させてクリアできるか。
3. 両方使うことで、初めて開く道・乗り継ぎ・別解があるか。
4. 両方の操作が必要でも、長い待機秒数や操作の忙しさだけを増やしていないか。

1・2で成立しても、もう一方が無価値とは限らない。別解や再挑戦の足場なら残す理由になる。ただし「複数石が必須の導入面」とは区別する。

前の構造案の「Stage 11で2石の役割分担を導入」は提案であり、mainの意図がそうだったと確定したものではない。原案の使われ方を確認するまで個数を減らさず、2石必須への改変も行わない。

## 今回の20面再設計への扱い

- Stage 1〜12の既存地形を読むことを先にし、旧候補の解法に地形を合わせない。
- 複数石の採用数・配置面は未確定。まずmainのStage 11で1石の場合と2石の場合を比較する。
- 追加する複数石には、乗り継ぎ、別経路、役割分担などの具体的な効果を求める。同時編集ができることだけを採用理由にしない。
- ユーザーとの会話では、本編はHTTPなしの4種類とし、HTTP操作は20面クリア後の解放機能とする方向になった。これは製品に実装された解放条件ではなく、設計方針である。
