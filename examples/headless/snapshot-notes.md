# Headless checkpoint prototype (decision required)

This PR provides an **exact replay-backed correctness oracle**, not an accelerated
copy of a running Bevy/Avian world. `Session::snapshot()` owns an immutable input
prefix; `restore()` builds a new App, replays that prefix, validates it, then swaps
it in. Restore remains O(k). It does not solve the search throughput goal and must
not be presented as a completed fast-snapshot implementation.

The strict no-product-behavior-change boundary matters: entity-only copies omit
Bevy system locals, message cursors/change ticks, and private Avian state. This PR
leaves product gameplay and dependencies unchanged. A fast native snapshot backend
needs a separate design decision and a broader implementation boundary.

## API and semantics

`src/headless/checkpoint.rs` exposes `Session::{new, step, advance_to, snapshot,
restore, report}` and `Snapshot::owned_bytes` within the binary's headless module.

- `step(&[KeyChange])` advances one driver frame. Scenario events apply first, then
  the supplied key transitions. Held keys persist. The caller cannot mutate World.
- Frame k means k completed driver updates (before input for frame k), not inclusive
  replay through input k. The bootstrap update has zero elapsed delta as before.
- Multiple snapshots can coexist; each is reusable and owns all its data. Branch
  inputs are included in snapshots taken on branches. Terminal runs can be restored.
- Terrain RON bytes, scenario, physics overrides, scales, seed, input overrides,
  script sensory/command transcript, frame count, terminal flag, and reference
  fingerprints are saved. The terrain path is not reread during restore.
- Report/trajectory prefixes, command IDs/results, all gameplay state, physics and
  script state are reconstructed by the same schedules. Restore validates the full
  sensory/command transcript, the existing per-frame execution digest (including
  body velocity and obstacle lifetime/collider state), and trajectory hash before
  replacing the current world. Divergence is an error and keeps the current world.
- No disk snapshot/import format is promised. Use the same executable, assets,
  architecture and dependency versions. Wall-clock `Instant`s and asset-loader
  bookkeeping are not simulation state and are not promised bitwise equality.
- The existing driver advances by `Duration::from_secs_f64(1.0 / 60.0)`. It does not
  override Bevy's separate `Time<Fixed>` timestep (default 64 Hz / 15.625 ms). Preserve its accumulator and
  existing physics cadence; changing that cadence would change motion baselines.

The product also inserts an unseeded `RAND_STATE_KEY` placeholder into ScriptState.
Neither current executor reads that field (and Keystone `rand` is rejected by
headless). The transcript excludes only this unused field; it is **not** a promise
to restore the process thread-local RNG. Obstacle/dynamic terrain use their seeded
streams. If an executor starts exposing the placeholder, this backend must reject
that API or explicitly record/replay its random inputs before claiming support.

No claim is made that every private Avian field has been individually compared.
Tests inspect available public state and exact frame-by-frame reports; regeneration
of private state relies on the same deterministic schedule and inputs.

## Program alternatives

1. **History replay:** implemented conservatively by replaying the whole simulation.
   The optional headless observer records each `next` call's stone index, observable
   ScriptState and yielded command. Restore checks the ordered transcript. This
   reproduces both languages, including sensory input, without cloning a thread.
   Sensor-only fast-forward is a later optimization, useful only with a correct
   physical checkpoint. Shared signals require replay in global call order.
2. **Keystone VM clone:** upstream `EventIterator` at the pinned revision derives
   Clone (stack and RuntimeContext), but its `api: Arc<dyn ExternalApi>` remains
   shared. The product wrapper transfers the iterator into an OS worker and keeps
   channels/stop flags. A headless-owned synchronous iterator and a rebound isolated
   API/signals state are promising; a shallow clone is not an independent snapshot.
3. **fork:** rejected. Even a no-code App uses Bevy asset/task-pool threads; programs
   add worker threads. Only the calling thread survives fork, with potentially
   inherited locked allocator/asset/channel state. Continuing arbitrary Rust/Bevy
   execution in that child is not a safe snapshot mechanism. Fork+exec is safe but
   loses the in-memory world and gives no advantage over replay.
4. **Native entity/resource clone:** not enabled. Public Clone on ContactGraph and
   PhysicsIslands alone is insufficient. For example Avian's AwakeIslandBitVec and
   ColliderCache are private; dynamic terrain RNG is a Bevy Local, and schedule
   system state is opaque. Exact cloning needs an explicit supported state boundary,
   stable entity identity/remapping and change/message state handling.

## Reproduce

```sh
cargo fmt --all -- --check
cargo clippy -- -D warnings
cargo test
cargo build --release --locked
python3 examples/headless/snapshot-benchmark.py
python3 examples/headless/snapshot-baselines.py
```

The benchmark invokes, with DISPLAY and WAYLAND_DISPLAY removed:

```sh
env -u DISPLAY -u WAYLAND_DISPLAY target/release/keystone-cc \
  --headless-measure-snapshot examples/headless/snapshot-terrain.json \
  --report target/snapshot-report.json
```

Use a scenario that can reach 1,000 frames without terminating. Otherwise the
benchmark errors instead of reporting a short prefix as a 1,000-frame sample.
The JSON includes 20 samples at 10/100/1,000 frames, one excluded warm-up, mean/max
snapshot/restore/full-replay latency and owned checkpoint bytes. Restore/replay
order alternates. Both include App initialization and old-world destruction; RON
file IO is excluded from both. Snapshot latency includes serialization and copying
report data for validation. Memory is the checkpoint object plus its owned boxed
payload, not RSS or peak working set: transactional restore temporarily owns two
worlds, and scripts have thread stacks. There is no CI speed threshold.

No algorithmic crossover exists for this backend: restore does the same replay plus
validation. Small measured advantages are noise. Full-replay benchmarks retain
script tracing too, so they compare the same instrumented Session driver; ordinary
`--headless-verify` can be faster. The separate baseline script runs the unchanged
verification CLI for all eight motion cases and stages 1/2, and compares the entire
six-scale reach summary. The frozen summary predates `player_physics` and
`motion_reference` metadata already present on main; only those two additive keys
are ignored when absent in the baseline. Every baseline value is compared exactly.

## Next decision

Keep this backend as a correctness oracle, but do not build A* on its performance.
Authorize a separately scoped native checkpoint experiment that can expose the
required system-local/private physics state (or a deterministic synchronous worker
model with a supported checkpoint boundary). Retain the same tests to reject any
partial-copy implementation. The 1,000 terrains / 5 minutes target is not established
by this PR; the future agent's branching factor and depth also need measurement.
